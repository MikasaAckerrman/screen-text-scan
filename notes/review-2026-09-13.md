## Вопрос 1: можно ли перестать выдавать спецвозможности?

**Факт:** Shizuku может читать И писать `settings secure enabled_accessibility_services`.
Запись подтверждена: `settings put secure ...` → exitCode 0, значение сохраняется.

**Ограничения:**
1. ScreenTextScan (обычный APK) не может сам вызвать Shizuku без:
   - добавления зависимости `dev.rikka.shizuku:api` + `dev.rikka.shizuku:provider`
   - объявления провайдера в манифесте
   - пользовательского разрешения через Shizuku Manager
2. Даже с Shizuku, запись `enabled_accessibility_services` из приложения-клиента
   помечена Android 13+ как требующая `WRITE_SECURE_SETTINGS`, а Shizuku даёт
   shell-uid, который это может. Но Android 14+ требует дополнительно
   `Manifest.permission.WRITE_SECURE_SETTINGS` для apps, обращающихся к Settings.
   Shizuku обходит это через shell-uid, но при вызове из app process через
   `IShizukuService` нужен явный grant.
3. На vivo OriginOS есть **отдельный** флаг `accessibility_enabled` (master switch).
   Его тоже надо ставить = 1.
4. `MY_PACKAGE_REPLACED` после обновления сбрасывает accessibility на некоторых
   прошивках — boot receiver уже это покрывает, но не сразу.

**Вывод:** Технически возможно через Shizuku API в самом APK. Но:
- Это требует добавления библиотеки Shizuku SDK
- Пользователь должен один раз разрешить Shizuku для ScreenTextScan
- После этого ScreenTextScan сможет сам включать свою службу при старте
- Это **не** постоянное решение: если Shizuku не запущен, придётся включать вручную

**Рекомендация:** реализовать опциональный путь через Shizuku, с fallback на ручное включение. Это лучший механизм: один раз разрешить в Shizuku Manager, и при каждом запуске ScreenTextScan сам проверяет и при необходимости включает службу.

## Вопрос 2: после выхода снова требует сканировать область

**Диагноз из кода:**
- `OverlayService.onStartCommand` → `showZoneSelector()` — **каждый запуск** показывает селектор зоны
- `ZonePrefs.load()` — сохраняет последнюю зону как **подсказку**, но не применяет автоматически
- Пользователь должен каждый раз нажать «Читать область» — это и есть «требует сканировать»

**Корень проблемы:** нет режима «повторить последний выбор». Зона сохранена, но не применяется.

**Исправление:** добавить опцию «Повторить» — если зона есть в `ZonePrefs`, сразу начать чтение с ней, без показа селектора. Селектор показывать только при первом запуске или по долгому нажатию.

## Вопрос 3: читать экраны с защитой от скриншотов

**Факт:** `FLAG_SECURE` на окне блокирует `MediaProjection` (скриншоты), но **НЕ** блокирует `AccessibilityService.getRootInActiveWindow()`. Дерево элементов доступно даже на защищённых экранах — потому что accessibility — это отдельный API, не связанный с surface flinger.

**Текущий код:** `accessibility_config.xml` — `canRetrieveWindowContent="true"` — этого достаточно.
`ScanAccessibilityService.readScreen()` → `getRootInActiveWindow()` — работает на `FLAG_SECURE` окнах.

**Вывод:** уже работает. Пользователь может не знать, что это работает — надо проверить на конкретном приложении с защитой.

## Вопрос 4: кнопка «Копировать» шлёт в приложение, а не в буфер

**Диагноз из кода:**
- `OverlayService.onBubbleTap()` → `openResult()` → `ResultActivity` — открывает экран правки
- `ResultActivity.doCopy(false)` — копирует в `ClipboardManager` — **правильно**
- НО: пользователь говорит «шлёт в приложение» — возможно, `openResult()` открывает ResultActivity вместо прямого копирования

**Корень проблемы:** тап по плавающей кнопке «Копировать» открывает экран правки, а не копирует сразу. Пользователь хочет:
- **Тап** = копировать в буфер немедленно
- **Зажатие 3 сек** = открыть экран правки (приложение)

**Исправление:** изменить `attachDragAndTap()`:
- короткий тап в состоянии DONE → `doCopyDirect()` (буфер + Toast)
- длинное нажатие ≥3 сек → `openResult()`

## Вопрос 5: скорость OCR и качество

**Факт:** приложение НЕ использует OCR. Читает дерево элементов через accessibility.
- Скорость: 50ms за обход дерева — это уже быстро
- Качество: 100% точность на текстовых элементах, 0% на картинках
- Нет «улучшения качества» через OCR — это другой механизм

**Реальная скорость:** POLL_MS=600ms — пауза между опросами. Можно уменьшить до 300–400ms.
Но 600ms выбран осознанно: обход 50ms, остальное — чтобы не пропустить текст при листании.

**Что можно улучшить:**
1. Уменьшить POLL_MS до 400ms (баланс скорость/батарея)
2. Добавить `includeDesc=true` для картинок с `contentDescription` — поднимает покрытие
3. Сейчас `readScreen(zone, screenW, screenH, false)` — `includeDesc=false`. Для экранов с иконками это пропускает текст.

## Полный список дефектов кода

### Критичные
1. **`OverlayService.lastRotationW/H` объявлены, но не используются** — мёртвые поля
2. **`OverlayService.onConfigurationChanged`** не пересчитывает `zone` через `ZonePrefs` — после поворота зона пересчитывается пропорционально, но не перезаписывается в `ZonePrefs` с новыми размерами
3. **`ResultActivity.pending` — static, переживает процесс** — если процесс убит, а ResultActivity не открыт, `pending` остаётся, и при новом запуске OverlayService `openResult()` передаёт старый накопитель
4. **`AccessibilityKeepAliveService.start()` из `onResume`** — если accessibility включена но `startForegroundService` из фона запрещён (Android 12+), catch глотает `ForegroundServiceStartNotAllowedException`, но не логирует — пользователь не знает, почему защита не работает

### Средние
5. **`ScanAccessibilityService.instance` обнуляется в `onUnbind`** — если система временно unbind/bind без уничтожения сервиса, `instance` может остаться null между `onUnbind` и новым `onServiceConnected`, создавая гонку
6. **`TextAccumulator.findGrowable`** — O(n²) на каждом опросе при большом количестве строк (1000+). На длинных документах это замедлит чтение
7. **`OverlayService.poll`** не проверяет `scanning` между `svc.readScreen` и `acc.addAll` — если пользователь нажал «Стоп» во время обхода, результат добавится в уже остановленный накопитель
8. **`ZoneSelectorView.onUp`** не вызывает `listener.onZoneChosen` — пользователь должен нажать кнопку «Читать область» отдельно. Это UX, не баг, но пользователь жалуется на «требует сканировать»

### Низкие
9. **`ScanTileService` ставит `STATE_INACTIVE` всегда** — даже когда чтение активно. Нет обратной связи «идёт чтение»
10. **`Permissions.isAccessibilityMasterOn`** default=1 — если настройка отсутствует (чистая прошивка), считается включённой. Должен быть default=0
11. **`ReadingOrder.joinRow`** — не используется в основном пути (`sort(items, false)`). Мёртвый код в production path
12. **`TextTranslator.translateAll`** — `String.join(" ", lines)` для определения языка: если 90% строк английские, но 10% русских, направление будет en→ru, и русские строки переведутся как english→russian, получив бессмыслицу
