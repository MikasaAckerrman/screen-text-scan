# Текст с экрана

Читает текст из любого приложения на Android: не распознаванием картинки,
а напрямую из элементов интерфейса. Поэтому ошибок распознавания не бывает,
а один опрос экрана стоит около 50 мс — против примерно 1500 мс у OCR снимка.

## Как пользоваться

1. **Плитка** в панели быстрых настроек — потянуть шторку, нажать.
2. **Выбор зоны.** Обвести пальцем область или нажать «Подобрать» —
   область содержимого найдётся сама. Рамку можно **подправить за ручки и
   перетащить**; заново обводить не нужно. Прошлый выбор предлагается сразу.
3. **Чтение.** Листайте текст. На кружке — число набранных строк, вокруг
   него кольцо: заполняется, когда с видимой части взято всё, и в конце
   сменяется галочкой «всё взято».
4. **Кружок нажать** — он расширится в «Копировать».
5. **Список результата.** Строки можно исправить, лишние исключить, всё
   вместе перевести. Только после этого текст уходит в буфер.

Результат дополнительно пишется в `screen-text.txt` в каталоге данных
приложения: буфер обмена недолговечен.

## Перевод

Работает **на устройстве** через ML Kit: языковая пара (русский ↔ английский)
скачивается один раз, около 30 МБ, дальше интернет не нужен. Прочитанный
текст никуда не отправляется — это принципиально, потому что приложение
видит содержимое чужих экранов.

Направление определяется по алфавиту. Строки без букв — числа, множители
`×1.30`, проценты — не переводятся: модель их только портит.

## Почему это приложение, а не скрипт

Три вещи вне приложения недостижимы принципиально:

- **плавающая кнопка поверх чужих приложений** — нужно окно типа
  `TYPE_APPLICATION_OVERLAY` и разрешение `SYSTEM_ALERT_WINDOW`;
- **плитка быстрых настроек** — системная сущность, объявляется манифестом;
- **буфер обмена** — с Android 10 запись доступна только приложению на
  переднем плане.

## Разрешения

| Разрешение | Зачем |
|---|---|
| Наложение поверх приложений | плавающая кнопка |
| Служба доступности | чтение текста активного окна |
| Уведомления | обязательное уведомление переднего сервиса |

Служба читает окно **по запросу**, а не по событиям: подписка давала бы
всплеск вызовов при каждой анимации. В простое расхода нет. Ни сети, ни
аналитики в приложении нет.

## Защита от повторов

Четыре уровня, каждый закрывает свой случай:

1. точное совпадение — строка не менялась между опросами;
2. совпадение после схлопывания пробелов и среза концевой пунктуации;
3. **наращивание**: новая строка содержит старую как начало или конец —
   значит в прошлый опрос строку застали недорисованной. Старая версия
   заменяется, место в списке сохраняется;
4. вложение: новая строка — обрезок уже сохранённой, отбрасывается.

Короткие строки (менее 12 символов) в наращивании не участвуют: «Да» —
начало «Дальше», и без порога кнопка «Да» исчезала бы из результата.

## Сборка

APK собирается в GitHub Actions. До сборки прогоняются три набора тестов и
сверка ресурсов — если сломана дедупликация, геометрия рамки или ссылки на
ресурсы, сборка не начинается.

Локально, без Android SDK:

```
# накопитель
javac -d out TextAccumulator.java TextAccumulatorTest.java && java -cp out TextAccumulatorTest
# геометрия (нужна заглушка Rect из tests/stub)
javac -d out android/graphics/Rect.java ZoneGeometry.java ZoneGeometryTest.java && java -cp out ZoneGeometryTest
```

## Что было измерено, а не предположено

**WebView отдаёт координаты в системе документа, а не экрана.** В браузере на
статье Википедии y шёл от −4297 до −3582 при экране 0…2800. Если применить к
таким строкам зону, останется 1 строка из 18. Поэтому строки с координатами
вне экрана помечаются виртуальными и через фильтр зоны проходят.

**Прямоугольники узлов бывают невалидными**: встречались `bottom` меньше
`top` (2712 против 2565) и отрицательные координаты. Это узлы, частично
уехавшие за границу окна. Без нормализации центр считается неверно.

**Нажатие отличается от перетаскивания по смещению, а не по времени.** Если
считать нажатием любое быстрое касание, короткий рывок при перетаскивании
останавливал бы чтение.

**Панель быстрых настроек надо закрыть до начала чтения** — пока она открыта,
активное окно это она, и служба прочитает саму панель. Закрытие происходит
только как побочный эффект запуска активности, поэтому плитка запускает
невидимый переходник, а не сервис напрямую.

**Поворот экрана обесценивает зону.** 1260×2800 → 2800×1260: те же числа
означают другое место, а кнопка уезжает за край и её не достать. Зона и
позиция кнопки пересчитываются пропорционально.

**Растягивание рамки за край не должно её сжимать.** Тест нашёл обратное:
первая версия нормализации сдвигала рамку целиком, из-за чего
противоположная сторона двигалась сама, хотя палец её не трогал.
