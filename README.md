# Текст с экрана

Читает текст из любого приложения на Android: не распознаванием картинки,
а напрямую из элементов интерфейса. Поэтому ошибок распознавания не бывает,
а один опрос экрана стоит около 50 мс — против примерно 1500 мс у OCR снимка.

## Как пользоваться

1. Плитка в панели быстрых настроек — потянуть шторку, нажать.
2. Обвести пальцем область, откуда читать. Есть и «Подобрать» — область
   содержимого находится сама, по самому большому прокручиваемому блоку.
3. Листать текст. Появляется маленькая полупрозрачная кнопка, на ней —
   счётчик набранных строк. Она перетаскивается куда угодно.
4. Нажать её. Кнопка расширяется и превращается в «Копировать».

Результат дополнительно пишется в файл `screen-text.txt` в каталоге данных
приложения: буфер обмена недолговечен, одно копирование в другом приложении
и текст потерян.

## Почему это приложение, а не скрипт

Три вещи вне приложения недостижимы принципиально:

- **плавающая кнопка поверх чужих приложений** — нужно окно типа
  `TYPE_APPLICATION_OVERLAY` и разрешение `SYSTEM_ALERT_WINDOW`;
- **плитка быстрых настроек** — системная сущность, объявляется манифестом;
- **буфер обмена** — с Android 10 запись доступна только приложению на
  переднем плане.

## Разрешения

| Разрешение | Зачем |
|---|---|
| Наложение поверх приложений | плавающая кнопка |
| Служба доступности | чтение текста активного окна |
| Уведомления | обязательное уведомление переднего сервиса |

Служба читает окно **по запросу**, а не по событиям: подписка на события
давала бы всплеск вызовов при каждой анимации. В простое расхода нет.
Данные никуда не отправляются — ни сети, ни аналитики в приложении нет.

## Сборка

APK собирается в GitHub Actions: `.github/workflows/build.yml`.
Готовый файл лежит в артефактах прогона.

Логика накопления текста не зависит от Android и проверяется до сборки:

```
javac TextAccumulator.java TextAccumulatorTest.java && java TextAccumulatorTest
```

## Что было измерено, а не предположено

**WebView отдаёт координаты в системе документа, а не экрана.** В браузере на
статье Википедии y шёл от −4297 до −3582 при экране 0…2800. Если применить к
таким строкам зону, останется 1 строка из 18. Поэтому строки с координатами
вне экрана помечаются виртуальными и через фильтр зоны проходят.

**Прямоугольники узлов бывают невалидными**: встречались `bottom` меньше
`top` (2712 против 2565) и отрицательные координаты. Это узлы, частично
уехавшие за границу окна. Без нормализации центр считается неверно и зона
отсекает всё.

**Нажатие отличается от перетаскивания по смещению, а не по времени.** Если
считать нажатием любое быстрое касание, короткий рывок при перетаскивании
останавливал бы чтение.

**Панель быстрых настроек надо закрыть до начала чтения** — пока она открыта,
активное окно это она, и служба прочитает саму панель. Закрытие происходит
только как побочный эффект запуска активности, поэтому плитка запускает
невидимый переходник, а не сервис напрямую.
